macOS build of EyeLeo, the Windows features brought over rather than the other way round.

This is 2.2.0. What is in it, newest first:

- The hydration reminder no longer freezes. Its countdown runs on the shared one-second clock, and the
  code that switched that clock off when a break ended did not know about the reminder, so the bubble
  stopped two seconds short and stayed on screen for good. The test for "is the clock still needed" now
  lives in one place and both callers use it. The same bug could freeze the "ready in N" countdown before
  a long break, which would have left the button permanently disabled.
- While a steep is running the short break, the hydration reminder and the long break all wait for it.
  A steep is short, so holding them costs nothing; once the steep has more than two and a half minutes
  left it can hold nothing further, which is the herbal schedule with its five to eight minute steeps.
  There the app wins and the brewing bubble is put away until the break is over.
- The brew bubble menu item stays grey until there is something to pour. It read as always-clickable
  because AppKit re-enables any menu item that has an action, overriding the rule; the menus now do not
  auto-enable. The strict-mode menu lock was dead for the same reason and works again.
- A sound plays at the end of every steep, the last one included. It is a system sound — the "Submerge"
  one in macOS terms, whose file is called Submarine — so nothing is shipped to make noise and the
  "Enable sounds" setting now governs more than the end of a long break.
- Red tea among the steeping schedules, at 95 C.

Tea schedules live in `tea.conf` next to the saved settings, and the copy in the app folder is a template:
the app copies it into its container on first run, and that copy is the one to edit.

Run the app from its own folder: every asset is loaded relative to the working directory.
