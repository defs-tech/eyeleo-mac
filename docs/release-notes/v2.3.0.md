macOS build of EyeLeo. This release is the dynamic menu: the teas come from a file rather than from
the program, and adding one no longer needs a rebuild.

This is 2.3.0. What is in it, newest first:

- The list of teas is read from `tea.conf` instead of being compiled in. A line added to that file
  turns up in the menu; a line deleted disappears from it, and the menu follows the file in the file's
  order. There is no second list anywhere in the program any more.
- A line is taken whole or refused whole, and the refusal says why. Refused are a name that is not one
  lowercase Latin word, a temperature outside (0, 100], a steep time that is not a whole number of
  seconds, more than eight of them, and a name already given. A rejected line leaves nothing behind, and
  the rest of the file is still used; only a file with nothing usable in it falls back to the built-in
  schedules.
- The name a tea is shown under is written on its own line, as `en="..."` and `ru="..."`. It used to be a
  `tea_name_<name>` key in the language pack, which lives inside the signed bundle where a person cannot
  write: a tea could be added with one line of `tea.conf` and could not be given a name at all. Both
  names are optional and either may be absent, and a tea with none of them is shown under its name from
  `tea.conf`. The name is quoted because it may contain a comma, and a comma outside the quotes is what
  separates the fields. A name in a language this build does not carry is dropped while the schedule is
  kept. The seven built-in teas carry both.
- Settings and `tea.conf` have moved from the app's sandbox container to `~/.config/eyeleo-mac`, which
  is where somebody actually goes looking for them. The container put them four directories deep under a
  name derived from the bundle identifier, which is a poor place to keep a tea schedule you meant to
  edit. This costs the app one sandbox exception, declared in `entitlements.plist` and limited to that
  one directory; it is the only thing in the app that reaches outside itself. Files from the old location
  are moved across once, on the first run after updating, and a failed move does not stop the app.
- Settings are no longer kept by `cfprefsd`. They are a plain `settings.xml` now, with the same section
  and key names as the Windows build. `cfprefsd` served reads from its own cache, so a file edited by
  hand was ignored by the running app; that is no longer possible to get wrong.
- A vessel is looked up by name, `tea_<name>.png`, and checked when it loads: PNG, 8 bits a sample,
  colour type 6 so there is a real alpha channel, and no larger than 142x88 px, the 71x44 pt corner of
  the bubble at 2x. Anything failing that is refused and the slot is left empty. A tea with no picture
  still brews, it just has no glass.
- Eight steeps is now a ceiling on macOS as it already was on Windows, and it is the length of the
  longest schedule that ships. macOS had no limit at all before.
- Diagnostics go to `stderr`, and only under `EYELEO_DEBUG=1`. There is no log file on macOS and there
  never was one; what the switch stops being is output going to a terminal nobody is looking at. So a
  `tea.conf` line that was refused is visible to whoever asked to look and to nobody else. Running the
  binary from a terminal with that variable set is still the only way to see any of it.
- `tea.conf` is created on first run from the template in the app bundle, into `~/.config/eyeleo-mac`. The
  notes for 2.2.0 said this already happened; it did not, and now it does. The template says where the
  vessels go and what they have to look like, so adding a tea does not mean hunting for a folder.
- `docs/tea.md` describes the whole thing end to end, and `tools/checktea.awk` checks a `tea.conf` against
  the same rules the parser uses without starting the app.

Nothing is added to your `tea.conf` behind your back. A file with fewer teas than the app ships means
those teas, and it stays that way until you put them back.

Water is not a tea and never was in this file. It has no steeping schedule, it cannot be added to
`tea.conf`, and it is not in the tea menu. It is the hydration reminder with its own settings and its
own glass.
